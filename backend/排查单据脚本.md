## 方案1：通过MySQL客户端排查（推荐）

在命令行执行：

```bash
# 假设你的MySQL密码为空，如果有密码请添加 -p密码
mysql -uroot finex_db -e "
SELECT 
    d.document_code AS '单据号',
    d.template_code AS '模板代码',
    d.template_name AS '模板名称',
    d.template_type AS '模板类型',
    d.status AS '单据状态',
    d.finished_at AS '审批完成时间',
    d.total_amount AS '总金额',
    u.company_id AS '提交人公司ID',
    u.username AS '提交人',
    p.push_status AS '推送状态',
    p.error_message AS '失败原因',
    p.voucher_no AS '凭证号',
    CASE 
        WHEN d.status NOT IN ('APPROVED', 'COMPLETED', 'PENDING_PAYMENT', 'PAYMENT_COMPLETED', 'PAYMENT_FINISHED') 
        THEN '❌ 单据状态不符合'
        WHEN d.template_type = 'application'
        THEN '❌ 模板类型是事项申请类（不能映射凭证）'
        WHEN d.template_type = 'loan'
        THEN '⚠️  模板类型是借款单'
        WHEN d.template_type IS NULL OR d.template_type = '' OR d.template_type = 'report'
        THEN '✅ 模板类型符合（员工费用类）'
        WHEN d.template_type = 'contract'
        THEN '✅ 模板类型符合（企业往来类）'
        ELSE '⚠️  未知模板类型'
    END AS '诊断结果'
FROM pm_document_instance d
LEFT JOIN sys_user u ON d.submitter_user_id = u.user_id
LEFT JOIN exp_voucher_push_document p ON d.document_code = p.document_code
WHERE d.document_code = 'DOC202301010001';
"
```

## 最可能的原因

根据我们刚才的代码修改，最可能的原因是：

**该单据的模板类型是 `application`（事项申请类）**

我们刚刚添加了新的过滤逻辑：
```java
if (!isVoucherEligibleTemplateType(document.getTemplateType())) {
    continue;
}
```

这个方法只允许 `report`（员工费用类）和 `contract`（企业往来类）通过，而 `application`（事项申请类）会被过滤掉。
