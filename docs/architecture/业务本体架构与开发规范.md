# FinEx 业务本体架构与开发规范

**状态**：首版实现说明（2026-10-12）。上位约束为[系统最终目标与开发架构规范](系统最终目标与开发架构规范.md)。

## 决策与边界

业务本体是 Agent 域维护的、经审核的通用产品语义目录。它解释实体、字段、枚举、关系、规则、指标和能力，不保存公司业务记录，也不承担授权或规则执行。Expense、Finance、Process 等业务域仍是业务事实、指标计算和状态校验的 owner。数据库索引只证明物理访问路径，不能单独充当业务关系；受控工具返回字段的关系由 Finance 确认后另行发布。首版使用 MySQL，不引入图数据库或向量数据库。

`ea_ontology_item` 以 `item_key + version_no` 保存草稿、发布和停用版本。编辑已发布定义时产生新草稿，旧版本继续生效；发布新版本时停用旧版本。每条定义记录业务域、来源、版本、审核人和生效区间。`ea_ontology_schema_binding` 只供服务端保存物理表字段映射，禁止进入模型可见 DTO。历史三张本体基础表可能包含未经审核的内容，迁移不会自动发布或复制它们；需由业务负责人逐条转为新目录草稿并审核。

## 对话接入与保密

FinWork 只从当前已发布、在有效期内的定义中检索相关术语，最多返回 12 条语义摘要。能力定义还须对应本次用户已有授权的固定版本工作流中的已注册工具。模型只看到名称、含义、别名、版本和必要关系，不看到物理表字段映射、工具编码、来源内部引用或真实业务数据。本体内容按不可信候选资料处理，不能覆盖系统提示词、执行权限或业务服务校验。

本体的录入和发布分属 `agent:business_ontology:edit` 与 `agent:business_ontology:publish` 权限。录入时阻止明显的邮箱、手机号、长数字和凭据值；审核者仍须人工确认没有公司名称、供应商、真实单据、金额、银行信息或内部政策。自动校验不能证明内容无秘密。规则与指标的说明仅用于理解，实际状态迁移和金额计算由对应业务服务执行。

## 财务术语与查询结果字段关系

增量脚本 `migrate_agent_ontology_finance_links_20261012.sql` 增加经核对的 Finance 通用术语和 `ea_ontology_result_link`。后者以固定受控工具编码及其 JSON 字段为端点，记录关系类型、解释、适用范围、审核版本，以及仅供服务端维护者核对的表/字段/索引或外键证据。关系随工具输出契约通过迁移维护，页面只读展示已发布版本；不提供任意表名、字段名或 SQL 的在线编辑入口。

例如序时账 `ccode` 对应科目档案 `subject_code`，项目 `citemccode` 对应项目分类 `project_class_code`。后者有 `(company_id,citemccode)` 复合外键；前者依赖同账套的编码约定及两侧索引，不宣称存在外键。余额表 `subjectCode` 与科目档案对应，但余额表是期间汇总，不能当成凭证分录逐行连接。父级科目与子级科目不得重复合计。供应商、客户和项目名称只供展示，关联以编码及相同账套为前提。

工作流完成全部受控工具的授权检查后，模型分析输入才加入本体上下文。关系只在来源工具实际返回相应 JSON 字段时提供；`targetInResult` 仅表示目标字段也出现在本次工具结果，`comparableScope` 只在两侧查询描述明确指向同一账套时为真，两者都不表示记录已核对匹配。模型可见内容只有通用术语、JSON 字段标识、关系说明及范围限制，没有物理索引证据。期间、权限仍以工具的查询描述和服务端校验为准，模型不得据此生成并执行 SQL。

## 部署与验收

1. 在已具备 `agent:business_ontology:view` 权限及 Agent 受控工具目录的环境，备份目标库后执行 `backend/sql/migrate_agent_business_ontology_20261012.sql`。脚本可重复执行；不会自动给普通角色增加编辑、发布或业务数据权限。
2. 核对两张新表、两个权限码和种子定义。系统种子中的规则与指标是待审核草稿；由 Expense 负责人确认口径后发布。已有环境的旧本体数据不自动暴露给模型。
3. 在基础脚本之后执行 `backend/sql/migrate_agent_ontology_finance_links_20261012.sql`，核对财务术语、8 条字段关系与只读页面。两份脚本均可重复执行；若现有种子需修改语义，应新增版本并停用旧版，不直接覆盖已审核历史。
4. 验收术语命中、草稿隔离、版本替换、过期过滤、能力权限过滤、无授权拒绝、空结果、跨账套/期间限制、汇总行不当分录、目标字段缺失、模型输入不含内部索引证据或敏感值。迁移前不得启用依赖本体查询的新服务版本。

回滚先停用本体发布与模型上下文接入，保留定义和审核记录；确认没有运行依赖后再评估是否删除新表。停用定义通过发布权限执行，不删除历史版本。
