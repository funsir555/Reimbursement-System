## 4. 架构约束

### 4.1 当前不做的事

- 不激进重命名
- 不先拆微服务
- 不回头重打已形成 owner 的大基座，除非复盘再次确认膨胀
- 不因为文档同步而改动业务协议

### 4.2 当前重点做的事

- 继续把残余 hotspot 压成 thin facade / thin coordinator 或清晰 owner
- 保持 controller URL、service 接口、DTO / VO 稳定
- 持续维护 focused tests 与全量回归基线
- 让 README、架构文档、配置说明、执行记录始终和仓库现状一致

## 5. 当前主要差距

与理想的长期蓝图相比，当前真正的差距主要在于：

- 少数大基座仍有二次膨胀风险
- 文档、配置说明、启动链容易出现事实漂移
- 前端大页面与复杂编辑器仍可能形成新的热点
- 热点批次需要靠统一 workflow 持续压制，而不是一次性“重做系统”
