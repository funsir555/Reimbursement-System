# 2026-04-20 阿里云 OCR 最小权限 RAM 用户落地方案

## 1. 目标

- 本方案只服务于“发票 OCR 调用”链路。
- 首期只覆盖阿里云发票识别 `RecognizeInvoice`，不提前放开发票验真或其它 OCR 能力。
- 核心目标是把阿里云 OCR 鉴权收敛为：专用 RAM 用户、最少 Action、后端保管密钥。

## 2. 账号与密钥模型

- 新建专用 RAM 用户：`finex-ocr-runtime`
- 默认不授予控制台登录权限；如必须排障，再临时开启并加 MFA。
- 为该 RAM 用户单独创建一组 `AccessKey ID / AccessKey Secret`。
- 这组 AK/SK 只允许：
  - 写入“系统设置中心 > API接口 > OCR”
  - 由后端运行时调用阿里云 OCR
- 明确禁止：
  - 复用主账号 AccessKey
  - 与其它云服务共用同一组 AK/SK
  - 把 Secret 下发到前端
  - 把 Secret 写入仓库、脚本或日志

## 3. 最小权限策略

### 3.1 首期发票 OCR 策略

- 策略名：`FinexInvoiceOcrRuntimePolicy`
- 首期最小权限只放行 `ocr:RecognizeInvoice`
- 阿里云 OCR 是操作级授权，`Resource` 只能写 `*`

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ocr:RecognizeInvoice"
      ],
      "Resource": "*"
    }
  ]
}
```

仓库内可直接复用模板：

- `C:\Users\funsir\Desktop\报销系统\backend\auth-service\src\main\resources\fixtures\ocr\aliyun-finex-invoice-ocr-ram-policy.json`

### 3.2 后续接发票验真时的升级策略

- 只有在项目真实接入发票验真后，才增加 `ocr:VerifyVATInvoice`

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ocr:RecognizeInvoice",
        "ocr:VerifyVATInvoice"
      ],
      "Resource": "*"
    }
  ]
}
```

仓库内可直接复用模板：

- `C:\Users\funsir\Desktop\报销系统\backend\auth-service\src\main\resources\fixtures\ocr\aliyun-finex-invoice-ocr-and-verify-ram-policy.json`

### 3.3 禁止项

- 不直接授予 `AliyunOCRFullAccess`
- 不在只做 OCR 阶段提前开放：
  - 通用文字识别
  - 表格识别
  - 身份证识别
  - 营业执照识别
  - 发票验真

## 4. 系统落地口径

### 4.1 系统设置中心

- 配置入口固定为：`系统设置中心 > API接口 > OCR`
- 只允许填写：
  - `AccessKey ID`
  - `AccessKey Secret`
  - `endpoint`
  - `connectTimeoutMs`
  - `readTimeoutMs`
  - `enabled`
- `AccessKey Secret` 只在写入时提交；读取时只能回：
  - `hasSecret`
  - `maskedSecret`

### 4.2 后端运行时

- OCR 调用全部由后端发起，前端不直连阿里云。
- 当前发票 OCR 链路只允许调用 `ocr:RecognizeInvoice`。
- “测试配置”继续使用项目内置发票样张，不使用业务真实附件。

### 4.3 日志与安全

- 后端日志中禁止打印：
  - `AccessKey Secret`
  - 完整 `Authorization` 头
  - 发票图片/PDF 原始二进制
- 错误信息必须区分：
  - 配置缺失
  - 权限不足
  - 厂商调用失败
  - 返回不可解析

## 5. 运维规则

- 建议采用双 Key 轮换：
  1. 新建一组 AccessKey
  2. 更新系统设置中心配置
  3. 执行 OCR 配置测试
  4. 上传测试发票验证识别
  5. 验证成功后禁用旧 Key
- 如果后续服务出口 IP 固定，可再增加 RAM 来源 IP 条件限制；如出口 IP 不稳定，先不启用该限制。

## 6. 验证清单

### 6.1 阿里云侧

- `finex-ocr-runtime` 已创建
- 已绑定 `FinexInvoiceOcrRuntimePolicy`
- RAM 用户不具备多余控制台权限

### 6.2 系统侧

- 系统设置中心能保存并测试阿里云 OCR 配置
- 发票附件上传后能完成真实 OCR
- 前端与日志中都看不到明文 Secret

### 6.3 边界验证

- 删除 `ocr:RecognizeInvoice` 后重新测试，预期返回权限不足
- 未接验真前调用 `VerifyVATInvoice`，预期失败

## 7. 结论

- 当前项目首期最小权限基线固定为：
  - 专用 RAM 用户：`finex-ocr-runtime`
  - 专用策略：`FinexInvoiceOcrRuntimePolicy`
  - 唯一放行动作：`ocr:RecognizeInvoice`
- 只有当项目后续明确接入发票验真时，才允许在该策略上增补 `ocr:VerifyVATInvoice`
