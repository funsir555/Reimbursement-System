本文档自发布之日起，作为系统设置模块后续工作的唯一实施基线。

## 2. 模块定义

系统设置模块是全局基础主数据与系统级配置中心，用于统一维护组织、人员、角色权限、公司主体、公司银行账户，以及当前已接入或预留的系统级接口配置。

系统设置模块必须服务于以下业务场景：

- 维护公司级组织树与部门负责人
- 维护系统用户、员工归属、统计归属与角色绑定
- 维护系统角色与权限树分配
- 维护公司主体及其银行账户主档
- 维护外部组织同步连接器与同步任务执行
- 维护 OCR 厂商配置并进行联通性测试

系统设置模块当前不负责以下内容：

- 普通员工个人中心信息维护
- 报销单运行态权限判定细则设计
- 财务档案专题页面的业务口径重定义
- 银企支付执行流程本身
- 发票验真真实渠道接入
- 通用配置中心、动态表单引擎或独立 IAM 产品

## 3. 核心口径与边界

### 3.1 模块归属口径

系统设置属于全局系统管理能力，不是财务管理的附属页，也不是流程管理的子页。

即：

- 主菜单入口继续独立归属 `系统设置`
- 前端主入口继续以 `/settings` 单页面多标签页承载
- 不允许把同一批系统级对象拆到“财务管理 / 流程管理 / 报销管理”下再各自维护一份
- 不允许围绕组织、员工、角色、公司再造第二套平行主数据中心

### 3.2 前端路由口径

当前系统设置前端基线以以下路由链路为准：

- `/settings`
- `/settings?tab=organization`
- `/settings?tab=employees`
- `/settings?tab=roles`
- `/settings?tab=companies`
- `/settings?tab=companyAccounts`
- `/settings?tab=apiInterfaces`

后续新增系统设置能力必须优先在 `/settings` 既有页签域内演进，不得随意拆出第二入口。

### 3.3 后端接口域口径

系统设置后端统一走以下接口域：

- `/auth/system-settings/bootstrap`
- `/auth/system-settings/departments/**`
- `/auth/system-settings/employees/**`
- `/auth/system-settings/roles/**`
- `/auth/system-settings/users/{id}/roles`
- `/auth/system-settings/permissions/tree`
- `/auth/system-settings/companies/**`
- `/auth/system-settings/company-bank-accounts/**`
- `/auth/system-settings/sync/**`
- `/auth/system-settings/ocr/providers/**`

后续新增系统设置能力必须优先在该域内扩展，不得另造平行控制器域。

### 3.4 权限口径

系统设置权限统一继续沿用 `settings:*` 命名空间。

当前至少已形成以下权限语义：

- `settings:menu`
- `settings:organization:*`
- `settings:employees:*`
- `settings:roles:*`
- `settings:companies:*`
- `settings:company_accounts:*`
- `settings:api_interfaces:*`

后续不得把同一类系统设置能力散落到其它无关权限域。

### 3.5 当前现状基线

当前系统设置模块的真实架构基线按以下实现理解：

- 前端主页面以 `SystemSettingsView.vue` 为中心
- 页面启动优先调用 `bootstrap` 聚合接口一次性拉取当前用户、组织、员工、角色、权限、公司、公司账户、同步连接器、同步任务和 OCR 配置
- 当前真实页签固定为 6 个：`组织架构 / 员工管理 / 权限管理 / 公司管理 / 公司账户管理 / API接口`
- 页面权限为空时显示“未被授予系统设置访问权限”，初始化失败时显示统一空态
- 主菜单“系统设置”独立出现在左侧导航，图标为 `Setting`
- 无权访问目标页时，系统优先回退到 `companyAccounts / apiInterfaces / organization` 中首个可访问页

后续所有扩展都必须建立在这套基线上，不允许忽略现状直接重写一套新体系。

## 4. 核心对象定义

### 4.1 部门

部门是系统设置中的组织树节点，用于承载公司归属、上下级关系、负责人、同步来源与统计归属。

部门当前至少包含以下语义：

- 部门 ID
- 部门编码
- 部门名称
- 父级部门
- 公司主体
- 部门负责人
- 同步来源
- 是否纳入同步管理
- 统计部门归属 / 统计大区归属 / 统计区域归属
- 状态与排序

### 4.2 员工

员工是系统设置中的全局用户主对象，用于承载登录身份、组织归属、岗位、统计归属和角色关系。

员工当前至少包含以下语义：

- 用户 ID
- 用户名
- 姓名
- 手机号 / 邮箱
- 公司主体
- 部门
- 岗位
- 劳动关系归属
- 统计部门归属 / 统计大区归属 / 统计区域归属
- 角色列表
- 同步来源与同步管理状态

### 4.3 角色与权限

角色是系统权限分配的主对象；权限树是系统菜单、按钮与操作能力的标准化授权集合。

角色当前至少包含以下语义：

- 角色 ID
- 角色编码
- 角色名称
- 角色说明
- 权限码集合
- 关联用户集合

当前系统内存在保留角色：

- `SUPER_ADMIN`

### 4.4 公司

公司是系统中的公司主体主对象，用于承载组织归属、员工归属、账务关联和公司级账户主档。

公司当前至少包含以下语义：

- 公司 ID
- 公司编码
- 公司名称
- 发票抬头
- 税号
- 状态

### 4.5 公司银行账户

公司银行账户是公司主体下的受控账户主档，用于承载公司收付款账户信息和银企直连配置来源。

公司银行账户当前至少包含以下语义：

- 所属公司
- 开户银行 / 省 / 市 / 网点
- 账户名
- 银行账号
- 账户类型 / 用途 / 币种
- 默认账户标识
- 启停状态
- 银企直连启用标识
- 直连提供方 / 渠道 / 协议 / 客户号 / AppId / 证书引用等扩展字段
- 最近直连同步状态

### 4.6 同步连接器

同步连接器是系统设置中外部组织同步的配置对象，用于维护平台开关、自动同步开关、同步频率和平台配置。

当前统一按以下口径处理：

- 已建表并纳入持久化对象：`sys_sync_connector`
- 当前支持的平台代码：`DINGTALK / WECOM / FEISHU`
- 迁移脚本默认种子状态：平台默认启用、自动同步默认关闭、默认同步间隔 60 分钟

### 4.7 同步任务 / 同步任务明细

同步任务是组织同步执行记录；同步任务明细用于记录每次同步中的具体动作与结果。

当前统一按以下口径处理：

- 任务主表：`sys_sync_job`
- 任务明细表：`sys_sync_job_detail`
- 当前任务主语义至少包括：任务编号、平台、触发方式、状态、成功数、跳过数、失败数、删除数、摘要、开始时间、结束时间
- 当前明细语义至少包括：明细类型、动作类型、业务主键、明细状态、明细消息

### 4.8 OCR 厂商配置

OCR 厂商配置是系统设置中 API 接口页当前唯一真实接入的外部能力配置对象。

当前统一按以下口径处理：

- 配置表：`sys_ocr_provider_config`
- 已定义厂商：`ALIYUN / TENCENT / BAIDU`
- 当前真实支持保存和测试的仅有：`ALIYUN`
- `TENCENT / BAIDU` 当前仅保留展示入口与待接入说明

## 5. 统一业务规则

### 5.1 组织架构统一规则

- 部门维护必须继续以单一部门树为准，不允许在不同模块各自维护部门副本
- 上级部门不得选择自己
- 同步部门不得直接删除，必须通过同步清理
- 删除部门前必须先删除下级部门
- 删除部门前必须先迁移该部门下员工
- 当前实现允许对同步部门保留“统计归属”层面的维护口径，但核心字段不得按手工部门同权处理

### 5.2 员工统一规则

- 员工主档必须继续由系统设置统一维护
- 同步员工不得直接删除，必须通过同步清理
- 删除员工前必须先调整该员工负责的部门负责人关系
- 同步管理员工的核心字段默认只读，不允许把外部同步对象当手工对象直接改写
- 员工保存与角色保存虽然页面联动，但仍属于“先保存员工主档，再保存用户角色”的两步语义

### 5.3 角色与权限统一规则

- 角色、权限树、用户角色分配必须继续由系统设置统一维护
- `SUPER_ADMIN` 是系统保留角色，不允许当作普通角色处理
- 当前基线下，`SUPER_ADMIN` 不允许通过普通前端流程编辑、删除或分配
- `SUPER_ADMIN` 权限调整只允许在受控高权限路径下处理，不得开放给普通角色管理员
- 前后端不得各自维护两套权限树或两套角色语义

### 5.4 公司统一规则

- 公司是组织、员工和公司账户的上游主对象，不得先删公司再让下游对象悬空
- 删除公司前必须先删除公司下部门
- 删除公司前必须先迁移公司下员工
- 删除公司前必须先删除公司下银行账户
- 后续任何依赖公司主体的配置扩展，都必须优先挂在现有公司主档之下，而不是另造平行主体表

### 5.5 公司银行账户统一规则

- 公司银行账户必须继续以公司维度统一维护
- 保存前必须完整选择开户银行、开户省、开户市和开户网点
- 账户名不能为空
- 银行账号不能为空
- 同一公司下银行账号必须唯一
- 默认账户语义必须唯一；当前实现会在设置默认账户时自动清理同公司下其它默认账户
- 账户停用时不得继续保留默认账户语义
- 公司账户中的银企直连字段属于账户主档从属配置，不得另造第二套直连账户配置中心

### 5.6 同步连接器与同步任务统一规则

- 组织同步当前统一归属系统设置，不得让流程管理、财务档案或报销运行态各自发起第二套同步
- 当前支持平台口径固定为：钉钉、企微、飞书
- 手动同步与自动同步都必须留痕到同步任务表
- 当没有可执行平台时，必须返回明确失败结果，不允许静默成功
- 平台未启用时，不允许执行同步
- 后端定时调度器按固定 60 秒轮询 due 任务执行，不得依赖页面常驻或人工点击维持后台同步

### 5.7 API 接口统一规则

- API 接口页当前只有 OCR 配置是“真实可保存、可测试、可被运行态消费”的能力
- 发票验真和接口文档当前仍属于静态占位，不得在需求沟通中误报为已接真实服务
- OCR 当前仅支持阿里云真实保存和真实测试
- 腾讯云、百度云当前只保留切换入口和待接入提示，不支持真实保存或测试
- 系统同时只允许一个 OCR 厂商处于启用状态
- 更换 `AccessKey ID` 时必须同时重新填写 `AccessKey Secret`
- OCR 测试必须继续使用系统内置样张执行一次真实识别，不得退化为假成功占位

### 5.8 防跑偏清单

后续每次改动系统设置前，至少先逐项确认：

- 是否仍然统一在 `/settings` 和 `/auth/system-settings/**` 既有边界内演进
- 是否没有把组织、员工、角色、公司等对象拆成第二套维护入口
- 是否所有用户可见文案都经过中文可读性与 UTF-8 检查
- 是否同步管理对象和手工对象的可编辑边界仍然清晰
- 是否 OCR、同步任务、公司账户等高风险配置仍有明确失败收口
- 是否影响财务档案、报销运行态、银企直连、发票识别等下游消费模块，若影响则已同步评估

## 6. 前端实施规范

### 6.1 页面与路由规范

- 系统设置主页面继续由 `frontend/admin-web/src/views/settings/SystemSettingsView.vue` 承载
- 路由和菜单元信息继续以 `frontend/admin-web/src/router/route-meta.ts`、`route-catalog.ts`、`navigation-config.ts` 为唯一基线
- 新增能力优先以页签、区块、抽屉、对话框形式在既有页面内扩展
- 不允许为同一对象再造第二套列表页、详情页或维护页

### 6.2 页面装配与数据加载规范

- 页面初始化优先继续走 `bootstrap` 聚合接口
- 组织、员工、角色、公司、公司账户、同步连接器、同步任务、OCR 配置必须保持统一装配来源
- 不允许各页签各自拼接一套新的初始化加载协议
- 初始化失败必须稳定落到空态，不允许整页永久 loading

### 6.3 文案与交互规范

- 所有用户可见文案必须使用 UTF-8 保存，并保证页面实际显示为可读中文
- “待接入”“只读”“同步清理”“默认账户”“已停用”等关键状态文案不得漂移
- 删除、停用、设为默认、运行同步、保存 OCR 配置等动作必须保留明确确认或结果反馈
- 页面不得以静默失败替代用户提示

### 6.4 组件与状态复用规范

- 系统设置内部页签应继续复用现有 composable、共享常量和类型模型
- OCR 厂商选项、同步平台名称、状态标签、账号脱敏规则应继续使用共享工具
- 不允许在不同页签里为相同状态含义定义不同中文口径

### 6.5 前端测试规范

后续触达系统设置前端能力时，至少应按变更范围补齐或回归以下测试基线：

- `SystemSettingsView.test.ts`

若改动涉及以下内容，必须补对应断言：

- 页签可见性与权限收口
- bootstrap 成功 / 失败 / 无权限空态
- OCR 厂商待接入提示
- 同步对象只读限制
- 角色保留对象保护
- 公司账户默认账户与启停交互

## 7. 后端实施规范

### 7.1 分层规范

- `SystemSettingsController` 只负责权限校验、入参绑定、HTTP 边界和标准返回
- 统一业务入口继续由 `SystemSettingsService` / `SystemSettingsServiceImpl` 收口
- 组织、角色、公司、同步、OCR 等细分规则继续留在专门的 settings domain support 中
- 不允许在 controller 中直接拼装复杂业务逻辑或直接操作 mapper

### 7.2 接口与异常规范

- 系统设置相关接口必须继续统一返回标准结果结构
- 组织、员工、角色、公司、公司账户、同步、OCR 的失败都必须可读、可追踪、可理解
- 不允许吞异常、半结构化返回、长时间 pending 或假成功
- 高风险动作必须返回明确中文错误，例如：
  - 同步部门不能直接删除
  - 请先删除下级部门
  - 请先迁移该部门下员工
  - 同步员工不能直接删除
  - 超级管理员角色仅允许通过数据库直接维护
  - 同一公司下银行账号已存在

### 7.3 领域规则规范

- 部门编码、用户名、角色编码、公司 ID、公司编码等主键或业务唯一键必须继续做唯一性校验
- 自动编码生成失败必须显式报错，不允许写入半成品对象
- 默认账户切换必须保持同公司范围内唯一
- 同步任务执行必须记录主任务与明细，不得只保留一个汇总结论
- OCR 厂商配置必须保留脱敏展示和密钥续用规则

### 7.4 定时任务规范

- 系统设置同步后台任务继续由 `SystemSettingsSyncScheduler` 统一调度
- 当前调度周期为固定延迟 60 秒扫描 due 任务
- 调度失败必须记录日志，但不得导致应用主线程异常退出
- 后续若新增更多同步平台或任务类型，必须继续纳入当前任务体系，不得并行再造第二套调度器

## 8. 数据与 SQL 规范

### 8.1 变更方式规范

- 系统设置相关表结构或种子数据变更只允许通过增量 SQL 落地
- 已落地的系统设置迁移基线继续以 `backend/sql/migrate_system_settings.sql` 为主
- 权限树刷新继续以 `backend/sql/refresh_system_settings_permissions.sql` 为主
- 禁止依赖手工改库来长期维持系统设置口径

### 8.2 当前表对象基线

当前系统设置至少已形成以下数据对象：

- `sys_company`
- `sys_company_bank_account`
- `sys_department`
- `sys_user`
- `sys_role`
- `sys_permission`
- `sys_user_role`
- `sys_role_permission`
- `sys_sync_connector`
- `sys_sync_job`
- `sys_sync_job_detail`
- `sys_ocr_provider_config`

后续任何扩展都必须优先在这些对象及其从属迁移中演进，不得平行复制一套同语义表。

### 8.3 初始化与默认状态规范

当前迁移脚本显示：

- 默认公司主体种子为 `GROUP_HQ / 集团总部`
- 默认部门种子为 `总部 / 财务共享中心 / 华东运营中心 / 总部职能中心`
- 默认 OCR 厂商种子为 `阿里云 / 腾讯云 / 百度云`
- 默认同步连接器种子为 `DINGTALK / WECOM / FEISHU`
- 默认同步连接器状态为“平台启用、自动同步关闭、间隔 60 分钟”

后续若要改变默认种子语义，必须先修订本规范并同步迁移脚本。

### 8.4 编码与字符集规范

- 所有系统设置相关 SQL 文件必须使用 UTF-8
- 表注释、字段注释、权限名称、菜单名称、厂商名称、平台名称必须保存为真实中文或清晰英文代码，不得乱码
- OCR、同步、权限和组织相关主数据不得因为脚本编码问题写坏

## 9. 权限与审计规范

### 9.1 权限语义

系统设置后续至少应规范以下动作权限：

- 查看系统设置菜单
- 查看组织、员工、角色、公司、公司账户、API接口
- 新增 / 编辑 / 删除部门
- 新增 / 编辑 / 删除员工
- 新增 / 编辑 / 删除角色
- 分配角色权限
- 分配用户角色
- 新增 / 编辑 / 删除公司
- 新增 / 编辑 / 删除公司账户
- 配置同步连接器
- 手动执行同步
- 编辑 OCR 配置
- 测试 OCR 配置

### 9.2 审计要求

以下动作默认视为高风险动作，必须留痕：

- 删除部门、员工、角色、公司、公司账户
- 修改角色权限
- 修改用户角色
- 保存同步连接器配置
- 手动执行同步
- 保存 OCR 配置
- 测试 OCR 配置
- 启停公司账户或切换默认账户

审计信息至少应记录：

- 操作者
- 操作时间
- 目标对象类型
- 目标对象主键或业务编码
- 关键输入摘要
- 操作结果
- 失败原因

## 10. 测试与验收规范

### 10.1 前端最小回归面

前端后续改动系统设置时，至少应验证以下场景：

- 左侧菜单“系统设置”按权限可见且可进入
- 6 个页签按权限正确显示或隐藏
- bootstrap 成功、失败、无权限三种状态都能稳定收口
- 部门新增、选择、配置保存、删除链路正常
- 员工新增、编辑、角色绑定、同步对象删除限制正常
- 角色新增、权限分配、用户分配、保留角色保护正常
- 公司新增、编辑、删除前置校验正常
- 公司账户新增、启停、设为默认、删除、脱敏展示正常
- OCR 页面阿里云可保存可测试，腾讯云/百度云只显示待接入提示

### 10.2 后端最小回归面

后端后续改动系统设置时，至少应回归以下测试基线：

- `SystemSettingsControllerTest.java`
- `SystemSettingsServiceImplTest.java`

若本次改动触达以下能力，必须补对应测试：

- 删除前置校验
- 同步任务执行与调度
- 默认账户切换
- 保留角色保护
- OCR 配置保存与测试

### 10.3 人工验收路径

每次较大改动后，至少应按以下路径做人工回归：

- 从左侧菜单进入“系统设置”
- 检查当前账号能看到的页签与权限是否一致
- 手工新增一个部门、一个员工、一个普通角色并完成基础维护闭环
- 新增一个公司账户并测试启停、设为默认、账号脱敏展示
- 在 API 接口页切换 OCR 厂商，确认阿里云和待接入厂商的交互差异正确
- 检查组织同步入口可见性、连接器配置保存和手动同步反馈链路

## 11. 与现有系统关系

### 11.1 与财务档案的关系

- 财务档案中的部门档案、员工档案当前消费系统设置中的部门与员工主数据
- 财务档案页不得自行复制一套员工或部门维护逻辑
- 若系统设置中的组织或人员口径变化，必须同步评估财务档案展示和查询兼容性

### 11.2 与报销运行态的关系

- 报销创建、审批、单据详情会消费公司、员工、部门、角色和公司账户等系统设置主数据
- 系统设置负责配置来源，报销运行态负责消费，不得各自维护一套冲突口径

### 11.3 与支付链路的关系

- 公司账户管理是银企直连和付款执行链路的主档来源
- 支付运行态不得绕开公司账户主档另造平行账户配置
- 账户直连扩展字段的口径变更，必须同步评估付款单与回调处理

### 11.4 与发票识别链路的关系

- OCR 厂商配置由系统设置维护
- 当前真实识别能力首期仅服务于发票附件上传后的 OCR 识别链路
- 发票验真与接口文档当前不属于已完成接入能力，不得在运行态假定其已可用

## 12. 后续实施约束 / 引用方式

后续任何系统设置相关页面、接口、权限、SQL、测试方案，都必须先对照本规范。

统一实施顺序如下：

- 先对照规范确认是否在边界内
- 再拆页面、接口、数据结构、权限和测试
- 最后进入开发、联调与验收

引用要求如下：

- 需求评审时，必须注明所对应的规范章节
- 页面方案、接口方案、权限方案、SQL 方案、测试方案必须逐项对照本规范
- 若需求与本规范冲突，必须先修订规范，再进入实现
- 未引用本规范的系统设置相关实现，默认视为规格不完整

本文档自发布之日起，作为“系统设置模块”后续工作的唯一基线文档。


## 数据库字段标准补充

- 涉及数据库建表、加列、改列时，所有表注释和字段注释必须使用真实中文，禁止 `column comment`、`table comment`、纯英文占位和 `?` 乱码。
- 金额字段统一使用 `DECIMAL(18,2)` 作为货币类型标准；费率、汇率、数量、工作量等非金额字段不得误套该规则。
- 新库只执行 `init*.sql`，旧库升级只执行 `migrate*.sql`，禁止手工点改数据库后不留脚本。
