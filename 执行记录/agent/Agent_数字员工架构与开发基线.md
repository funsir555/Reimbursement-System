## 1. 产品定义与首版范围

数字员工是企业管理的查询服务层。工作台负责工作流画布、Prompt、模型和工具；作者将**已发布的固定版本**提交企业共享，审核后数字员工才可绑定。数字员工负责责任人、使用者分配、服务范围、定时计划和运行观察。FinWork 负责提问、结果和用户主动订阅的站内收件箱。数字员工配置只会缩小数据范围，不产生业务授权。

首版仅开放报销单只读查询和指定会计期间的未结账公司数。一个员工可绑定多个查询工作流；多人、多公司均受逐项角色数据范围控制。审批、付款、任意自然语言定时任务及外部通知不在首版范围。工作流作者和数字员工责任人可以不同；具备审核权限的作者可自审，提交、审核、驳回、撤销均保留记录。新版发布不会自动替换现有绑定。

## 3. 授权模型与执行顺序

### 3.1 有效授权

服务端将查询权限码和数据范围从**同一有效角色**解析为 `QueryAuthorization`，再取提问者、数字员工责任人、员工按能力配置的公司上限、工作流工具和业务对象范围的交集。同一查询码下多角色范围可合并；一个角色的宽范围不能借给另一个角色的查询权限。普通角色没有范围配置即无该 Agent 查询权。超级管理员对有效查询能力固定取得当前默认租户的全部启用公司，无须在数据范围表中手工配置。既有角色码为 `SUPER_ADMIN`；服务端与页面统一按不区分大小写的角色码识别，避免早期实现用小写字面量导致授权失效。

目前 `sys_company`、`sys_role` 等基础表是全局单租户结构，HTTP Agent 上下文使用 `default` 租户；授权解析对显式的非默认租户拒绝，避免误把全局公司数据当作其他租户权限。未来引入真正多租户基础表前，不得移除此拒绝条件。

`SELF` 在本人单据模板中匹配本人提交记录，在分配给本人模板中还须匹配实际任务关系；两者可跨当前任职公司，但单据归属公司必须在当前租户的有效公司集合内。`DEPARTMENT_TREE` 根据当前部门树和在职用户动态计算；`SELECTED_COMPANIES` 只允许已选且启用的公司；`ALL_COMPANIES` 包含全部启用公司。财务期间统计能力仅声明公司范围，不能将个人范围用于公司计数。授权上下文摘要随受控回答和定时投递保存，用于撤权后读取复核。

### 3.2 同步查询链路

1. FinWork 识别报销或结账查询意图，仅枚举**已分配给提问者**、状态启用、共享仍获批准、固定版本仍发布且工作流启用的数字员工绑定；没有全局候选或内置回退。受控查询使用审核通过的固定版本内模型配置，聊天端模型选择不能覆盖它。
2. 候选工作流校验受控工具与查询能力一致，且双方角色数据范围有交集。存在多个候选且不能唯一确定时，回答需用户选择员工或工作流。
3. Expense、Finance 业务域只读端口用服务端授权集合构造数据库条件，先过滤再计数、分页或形成证据。客户端公司参数只能缩小有效范围。财务期间不明确时先要求用户给出年度和期间。
4. 模型只接收脱敏后的报销上下文；最终报销数量和财务数量来自业务端口。外部模型文字不决定统计值。运行结束前重新读取授权和绑定状态，比较摘要后才返回结果。
5. 查询回答写入 FinWork 时单独保存来源元数据；历史读取再次校验当前分配、固定版本、责任人及权限摘要。无来源元数据的旧受控回答按无权处理。

受保护查询无权限时统一返回“系统查询到您没有相关权限，请换一个问题”；授权后确无记录返回零；可见范围受限时提示“仅统计您有权查看的范围”。普通运行日志仅存非敏感状态、数量和关联 ID。FinWork 和定时运行的受控运行详情隐藏原始输入、输出、自定义节点名称和敏感错误，只展示白名单中的步骤类型、状态与耗时。工作台手动测试运行另设受限调试查看路径，要求日志权限和运行归属；测试查询仍按测试者的数据范围执行。

同步修复了 `/auth/finance/general-ledger/period-status/overview` 的公司校验：传入公司须在当前用户该财务查询能力的有效范围内；未传公司而有效公司不唯一时要求选择。`reopen`、`unpost` 也复核所指公司。公司存在、启用或总账可用均不能代替用户数据范围校验。遗留 `ExpenseQueryTool` 已改走同一授权端口，移除了可直接按客户端公司查询的旧端口方法。

### 3.3 定时链路

计划只保存每日、每周、每月频率和已验证的模板参数。财务模板要求 `year` 与 `period`；报销模板只接受 `MY`、`ASSIGNED`、`VISIBLE`。启用计划前须配置每日运行上限与并发上限。用户在 FinWork 自行订阅后，每次触发按用户分别创建运行和结果；数据库唯一键 `(plan_id,user_id,scheduled_at)` 与计划到期时间条件更新防止重复调度。同一员工的当日投递数和运行中数控制预算，达到上限将计划暂停并留下审计；共享或固定版本失效将计划暂停为授权异常。

执行前、查询后送达前、收件箱读取时均重新计算授权。撤销用户分配、共享批准或角色范围后，旧敏感结果在收件箱隐藏。结果与聊天分表存储：投递保存最小文本、授权摘要、来源与失败码，普通日志不保存原始记录。当前调度器按实例顺序执行；**多实例部署的预算并发原子预留和异常进程恢复尚未验证**，首版运行拓扑应保持单实例，扩容前补充配额租约机制及压力回归。

## 9. 2026-10-02 第一阶段：报销复合查询与权限闭环

### 9.1 实现范围

- FinWork 先由服务端读取当前用户获分配的数字员工、已审核并发布的固定工作流版本，再将名称、说明及获审核的 Prompt/Guardrails 作为候选资料交给固定编排模型。模型返回结构化计划；服务端逐项核验绑定 ID、权限与查询参数，最多顺序运行四个现有只读工作流。需要选择时保存十五分钟的会话澄清状态，并在原会话展示选项。受保护业务提问不回退到普通聊天猜答。
- 报销工作流将“总金额”视为结果上的分析要求。Expense 端口对完整授权匹配集计算 `COUNT` 与 `BigDecimal SUM`，列表最多展示五十条并标明匹配总数及展示条数。单个报销工作流的总金额来自业务聚合，不由模型猜数；多个报销工作流可能重叠时不直接相加。金额字段不按名称默认脱敏，记录仍先受授权过滤。
- 报销列表、审批待办、付款单、个人未结事项、单据查询以及详情、打印、关联附件读取增加逐项角色范围与对象关系校验。通用附件预览对未关联附件校验上传者；已关联单据的附件重新检查当前单据读取权。旧附件没有上传者元数据时，通用入口保守拒绝，仍可通过有权限的单据关联入口读取。
- 现有账簿九类查询、元数据和 Excel 导出按各自查看权限的数据范围校验公司；导出仍需原有导出权限。期间状态接口已有指定公司范围校验，本阶段保留并回归。
- 报销异步导出在提交、任务执行和下载时校验范围，保存最小来源摘要；缺少来源记录的旧敏感导出不再交付。FinWork 每个复合回答保存全部工作流来源，历史读取重新校验分配、版本、责任人、授权摘要和报销源单据快照；来源项数量不完整时拒绝读取。
